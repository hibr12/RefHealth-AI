# Feature: AI-Powered Incoming Referral Prioritization and Intelligent Queue Management

## 1. Objective

Implement an AI-powered incoming referral prioritization and intelligent queue management feature in **RefHealth AI**.

The purpose is to help receiving hospitals manage referrals arriving from multiple health centres and other referring facilities. When a hospital receives many referrals, the system should intelligently prioritize them according to their clinical urgency and organize them using the exact time each referral arrives at the receiving hospital.

The system must help hospital staff identify which referrals require attention first, which have been waiting longest, and which are approaching or exceeding their acknowledgement deadlines.

This feature must integrate with the existing RefHealth AI architecture without breaking existing functionality.

## 2. AI-Powered Clinical Prioritization

When a referral arrives at a receiving hospital, the AI service should analyze the available referral information and recommend an appropriate clinical priority.

The system should support four priority levels:

- **Critical:** Requires immediate attention according to approved clinical protocols.
- **High:** Requires urgent attention.
- **Medium:** Requires timely attention.
- **Low:** Can be handled through the normal workflow.

The AI should consider available structured information, including:

- Clinician-assessed urgency.
- Patient symptoms and referral reason.
- Available vital signs and clinical observations.
- Identified risk indicators.
- Required medical service or specialty.
- Other relevant clinical information recorded in the referral.

The AI must provide an understandable explanation for each recommended priority, identifying the factors that influenced its recommendation.

**Important clinical safety requirements:**

- Do not use an LLM as the sole clinical prioritization mechanism.
- Use clinically reviewed and approved rules or validated models for clinical prioritization.
- Do not invent clinical thresholds or medical protocols.
- Missing clinical information must not automatically result in LOW priority.
- If information is insufficient, mark the referral as requiring clinical review.
- Clearly distinguish AI-recommended priority from clinician-confirmed priority.
- Authorized hospital staff must be able to review and override AI recommendations.
- Require a reason whenever a staff member manually changes a priority.
- Record all priority changes for auditing.
- Emergency cases must follow the hospital's approved emergency escalation procedures.

AI recommendations must support clinical staff, not replace their professional judgment.

## 3. Exact Receiving-Hospital Arrival Time

The system must accurately record the exact time each referral reaches the receiving hospital.

This is a critical requirement.

Do not use the referral creation or submission time as the hospital arrival time.

Maintain separate timestamps:

1. **Submitted At:** When the referring facility submits the referral.
2. **Received At:** When the referral actually reaches the receiving hospital's system.
3. **Acknowledged At:** When the receiving hospital officially acknowledges the referral.

The `received_at` timestamp must be generated by the backend server when the referral is successfully received.

Requirements:

- Store timestamps consistently in UTC.
- Display timestamps in the receiving hospital's local timezone.
- Prevent ordinary users from arbitrarily modifying the actual arrival timestamp.
- Calculate how long each referral has been waiting since its arrival.
- Preserve the original arrival timestamp throughout the referral lifecycle.

## 4. Intelligent Referral Queue Ordering

Create an intelligent incoming referral queue for each receiving hospital.

The queue must follow these ordering rules:

**Rule 1: Clinical priority comes first.**

Critical referrals must appear before High, High before Medium, and Medium before Low.

**Rule 2: Arrival time determines order within the same priority.**

When multiple referrals have the same clinical priority, the referral that arrived earliest at the receiving hospital must appear first.

For example:

| Referral | Priority | Received At |
|---|---|---|
| REF-001 | Critical | 10:30 AM |
| REF-002 | High | 09:15 AM |
| REF-003 | High | 09:45 AM |
| REF-004 | Medium | 08:30 AM |
| REF-005 | Critical | 10:45 AM |

The correct queue order is:

1. REF-001 — Critical, 10:30 AM
2. REF-005 — Critical, 10:45 AM
3. REF-002 — High, 09:15 AM
4. REF-003 — High, 09:45 AM
5. REF-004 — Medium, 08:30 AM

This means an older Medium referral must not automatically appear above a newer Critical referral.

**Rule 3: Waiting time must remain visible.**

Display the waiting duration for every referral so hospital staff can identify referrals that have been waiting for a long time.

Waiting time must not silently downgrade or replace clinical priority.

## 5. Acknowledgement Deadline and Escalation

Implement an acknowledgement monitoring mechanism.

Each receiving hospital should be able to configure acknowledgement deadlines according to its operational policies.

The system should:

- Track how long each referral has waited without acknowledgement.
- Identify referrals approaching their acknowledgement deadlines.
- Identify overdue referrals.
- Display appropriate warning indicators.
- Generate escalation notifications for authorized hospital staff.
- Record when an escalation occurs and why.

Do not invent universal acknowledgement deadlines. Use configurable hospital policies.

Keep clinical urgency separate from operational waiting-time escalation.

For example, a Low-priority referral that has waited too long may receive an overdue warning, but that warning must not automatically change its clinical priority to Critical.

## 6. Incoming Referral Dashboard

Create a dedicated incoming referral management dashboard for receiving hospitals.

The dashboard should display:

- Referral ID.
- Patient information according to the user's permissions.
- Referring health centre or facility.
- Referral submission time.
- Actual receiving-hospital arrival time.
- Waiting duration.
- Required medical service or specialty.
- AI-recommended priority.
- Clinician-confirmed priority, where available.
- AI explanation.
- Acknowledgement status.
- Acknowledgement deadline.
- Escalation status.

Provide filtering and sorting options for:

- Clinical priority.
- Referring facility.
- Required medical service.
- Referral status.
- Arrival date and time.
- Waiting duration.
- Acknowledgement status.
- Overdue referrals.

The dashboard must make Critical and High referrals easy to identify visually without relying on color alone.

## 7. Dynamic Queue Updates

The incoming referral queue must update whenever an important event occurs.

Examples include:

- A new referral arrives.
- A referral's clinical priority changes.
- A clinician confirms or overrides an AI recommendation.
- A referral is acknowledged.
- An acknowledgement deadline is approaching or exceeded.
- A referral is rejected, cancelled, or completed.

Use the existing real-time communication mechanism if the project already has one. Otherwise, implement an appropriate mechanism that fits the current architecture.

Avoid unnecessary page reloads.

## 8. Audit and Accountability

Maintain an audit history for important actions.

Record:

- Referral arrival.
- AI priority recommendation.
- Clinician confirmation.
- Manual priority changes.
- Previous and updated priority.
- Reason for manual changes.
- User who performed the action.
- Timestamp of the action.
- Acknowledgement events.
- Escalation events.
- Relevant queue status changes.

Only authorized users should access sensitive patient and audit information.

## 9. Integration With Existing RefHealth AI Components

Integrate this feature with the existing AI components:

1. **Referral Acknowledgement Delay Prediction:** Use predictions to help identify referrals that may experience acknowledgement delays and support operational monitoring.
2. **Intelligent Hospital Recommendation:** Preserve the existing hospital recommendation workflow.
3. **Next-Day Hospital Workload Prediction:** Use workload forecasts to help hospital administrators understand operational capacity.

These components must remain logically separate.

In particular:

- Hospital workload must not determine clinical urgency.
- Predicted acknowledgement delay must not determine clinical urgency.
- Clinical priority must not be reduced because a hospital is busy.
- Operational predictions may support staffing, monitoring, and escalation decisions.

## 10. Technical Implementation Requirements

Before implementing anything, inspect the existing project structure and understand the current referral workflow, database schema, authentication, permissions, frontend, backend, and AI-service integration.

Use the existing architecture:

- **Frontend:** Existing RefHealth AI frontend.
- **Backend:** Existing Node.js/Express API.
- **Database:** Existing PostgreSQL database with Prisma ORM.
- **AI Service:** Existing Python/FastAPI AI service.

Implementation requirements:

- Reuse existing referral entities and relationships wherever possible.
- Extend the database schema only when necessary.
- Create appropriate API endpoints for incoming referral queues, priority recommendations, priority overrides, acknowledgement tracking, and escalation.
- Apply role-based access control.
- Validate all incoming data.
- Handle AI-service failures safely.
- Ensure the referral workflow continues to operate if the AI service is unavailable.
- Maintain consistency between backend, database, and AI service.
- Avoid duplicate functionality.
- Do not introduce unnecessary technologies or unrelated features.

## 11. Expected Final Result

After implementation, each receiving hospital should have an intelligent incoming referral management system that:

1. Receives referrals from different referring facilities.
2. Records the exact time each referral reaches the receiving hospital.
3. Uses AI to recommend clinical priority based on available clinical information and approved protocols.
4. Organizes referrals by clinical priority.
5. Uses earliest receiving-hospital arrival time to order referrals within the same priority.
6. Calculates and displays waiting duration.
7. Monitors acknowledgement deadlines.
8. Identifies overdue referrals and supports escalation.
9. Allows authorized clinicians to review and override AI recommendations.
10. Maintains a complete audit history.
